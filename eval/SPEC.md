# AI文规范 v0.1

> **AI文 = 用 tokenizer 认识的字，写清因果与约束的压缩语。**
> 选词标准不是「雅」，是「BPE 里有它」；删减标准不是「短」，是「删了不产生歧义」。

---

## 1. 它不是什么

| 常见误解 | 事实 |
| --- | --- |
| 是文言文 | 不是。文言追求古雅，AI文追求**词表命中**。`蒹葭苍苍` 6 token、`饕餮` 各 2–3 token——文言里最雅的部分，正是 tokenizer 里最贵的部分 |
| 是摘要 | 不是。摘要压的是**语义**（丢信息），AI文压的是**形式**（虚词、语序、重复），一个字的信息都不丢 |
| 是压缩算法 | 不是。实测它只比原文省 11–25%，比碎片摘要贵约 3 倍。它是**保真编码** |

## 2. 它解决什么

现有插件的记忆注入是「碎片」：`尝试 JWT 鉴权失败，已回滚 session 方案。`
短、便宜，但丢了**为什么失败**（refresh 轮换）、**失败长什么样**（登录失败）。下次遇到同类问题，Agent 只能重踩一遍。

AI文要的是：**在保住因果链的前提下，最短的那一版。**

## 3. 八条规则

| 编号 | 规则 | 做法 |
| --- | --- | --- |
| **A1** | 删尽虚词 | 的/了/是/在/就/都/也/很/然后/其实/大概/一下/这种 |
| **A2** | 主体默认化 | 默认主体是「用户/本项目」；**只在切换主体时标**（甲/乙/用户/库） |
| **A3** | 只用高频字 | 改·增·删·停·启·换·回·测·验·发·批·拒·败·成·卡·慢·稳 ✅　缮·厘·易·亟·遂 ❌ |
| **A4** | 关系符号化 | 见下节符号表 |
| **A5** | 保真不删 | 否定 · 数量 · 时间 · **条件（若/则/除非）** · 情态（必须/不要/可） · 专名与标识符（URL/路径/错误码/版本/API 名，**原样保留**） |
| **A6** | 一行一断言 | 两个断言不能合并——合并了就没法单独失效、单独回源 |
| **A7** | 尾部三元 | `@时间 #来源 !置信`（`!` 高 · `?` 中 · `~` 低） |
| **A8** | 禁表 | 典故、成语、生僻字、之乎者也、非项目内高频的缩写 |
| **A9** | **符号优先，语言不换** | `→` `=` `!` `?` `+` `-` `~` `@` `#` 与标识符（`JWT` `ENOENT`）永远优先——它们在所有分词器上都是 1 token。~~语言替换~~：真值实测 42 个概念里只有 3 个换英文能省 1 token，4 个反而更贵，**默认不做**（见 `CALIBRATE.md` §7）。若要做，必须逐词实测并登记别名 |

## 4. 符号表

| 符号 | 含义 | 例 |
| --- | --- | --- |
| `→` | 导致 / 变成 | `正斜杠→配置读败` |
| `←` | 来自 | `403←缺tenant头` |
| `=>` | 推出 | `多实例=>不一致` |
| `=` | 定义 / 等同 | `后端=老王` |
| `+` `-` | 增 / 删 | `必通登录+支付` |
| `~` | 约 / 近似 | `~3天` |
| `@` | 时间 | `@2026-10-24` |
| `#` | 来源（回 L0） | `#12` |
| `!` | 红线 / 高置信 | `!禁无备份迁移` |
| `?` | 未决 / 中置信 | `?缓存未定` |
| `□` | 待办 | `□补测试` |
| `vs` | 对比 | `Redis vs 本地LRU` |
| `&` | 并列 | `登录&支付` |
| `≤ ≥` | 阈值 | `函数≤40行` |

## 5. 行格式

```
正文。@时间 #来源 置信尾标
改登录鉴权→JWT，refresh轮换→登录失败，故回滚session。@2026-10-24 #12 !
```

**三档不同的只有尺寸，规则本身相同：**

| 档位 | 汉字上限 | 字符上限 | `@时间` | 置信尾标 | 典型用途 |
| --- | ---: | ---: | --- | --- | --- |
| 题 `title` | 12 | 24 | 可省 | 可省 | 标题、指针、Outline 节点 |
| 轻 `lite` | 45 | 90 | 必填 | 必填 | 分页首批、低预算注入 |
| 全 `full` | 45 | 90 | 必填 | 必填 | 证据包正文 |

- 三档都**必须带 `#来源`**
- 一行最多一个 `。`，且必须在正文末尾
- 开头可以有一个 `!`（红线）或 `?`（未决）标记
- 校验：`node lint.mjs --tier title examples.title.aiw`

**尾部不是注入内容。** `@时间 #来源 置信` 是**写作与校验格式**：入库时拆成结构化字段
（`validFrom` / `source` / `confidence`），注入时剥掉。实测这一步省 31% token、
准确率掉 1 个百分点（见 §8）。

## 6. 三条硬约束

1. **必须有 `#来源`**，指回 L0。AI文永远是投影，不是原文——它天然携带「我不是原话」的体裁标记。
2. **L1 双表示**：`claim.body`（白话规范）+ `claim.aiw`（派生）。注入用 aiw，审计/迁移/换模型用 body。**压缩不能成为唯一的真相形态。**
3. **lint 不过不入库**（`node lint.mjs`）。
4. **换编码必须登记别名**（`aliases.mjs`）。闸门按别名判定保真：`auth` 算保住 `鉴权`。别名表必须**固定、可审计**——不允许模型临时生成，否则闸门会被"我换了个说法"绕过。

## 7. 实测结果（v1.0，30 条记忆，93 个事实，200 题）

token 为 `deepseek-chat` 真值；答对率来自 200 题评测（7 种注入条件）。

| 档位 | token | 事实保真 | disc 答对 | base 答对 |
| --- | ---: | ---: | ---: | ---: |
| 原文（L0） | 952 | 96.8% | — | — |
| **AI文·题** | 247 | 61.3% | 38% | 61% |
| **AI文·轻** | 533 | 91.4% | 77% | 70% |
| **AI文·全（含尾）** | 965 | 97.8% | 87% | 74% |
| **AI文·全 + 符号表** | 965 | 97.8% | **90%** | 74% |
| **AI文·全 · 无尾** | **665** | 97.8% | **89%** | 74% |
| 碎片（基线） | 210 | 21.5% | **0%** | 74% |

- **disc = 102 题**：目标事实在 AI文、不在碎片
- **base = 23 题**：两边都有（回归）
- **abstain = 75 题**：记忆里没有（应回答「不知道」）

## 8. 剥离尾部元数据：省 31% token，掉 1 个百分点

这是这一版最重要的一条，而且是被数据逼出来的：

**问题**：`AI文·全（含尾）` 965 token，比原文 952 还贵。原因是 `@2026-10-24 #12 !` 这类尾部元数据被算进了正文。

**改法**：正文只留 body；`时间 / 来源 / 置信` 变成结构化字段（`validFrom` / `source` / `confidence`），注入时不进正文。

**结果**：

| | token | disc 答对 |
| --- | ---: | ---: |
| 含尾 | 965 | 90% |
| **无尾** | **665** | **89%** |

**省 31%，准确率掉 1 个百分点——落在噪声内**（同一配置两次运行，base 列就波动了 4pp）。

所以：**尾部是记账数据，不是记忆内容。** 它该进数据库，不该进上下文。

> 顺带解释了一个旧异常：12 题时「轻档比全档答得对」，很可能就是尾部噪声造成的——轻档的尾部更短。

## 9. 三档怎么选

| 场景 | 档位 | 理由 |
| --- | --- | --- |
| 标题、指针、Outline 节点 | **题** | 只要「找得到」；disc 38%、base 61% |
| 分页首批、低预算注入 | **轻** | 200–800 token 区间的最优解，disc 77% |
| 证据包正文 | **全 · 无尾** | disc 89%，且比原文便宜 30% |
| 原文 | L0 | 永不注入，只回源、审计、重建 |

三档共用一套规则；铁律是：**任何一档都不许删标识符、数字、否定、因果箭头。**

**不再有「碎片」这个类型。** 它是一次失败的压缩档位：disc 0/102，base 也只有 74%——它只保住了它本来就有的那部分。

## 10. 已知局限

1. **分词器**：`用户彻底怒了` 在 DeepSeek 是 3 token，o200k 是 5，cl100k 是 8。本文所有 token 数已用 `deepseek-chat` 真值复测（见 §7）；**换模型必须重测**。
2. **作者偏差**：语料、碎片、must_keep 都由作者编写。
3. **硬匹配**：`#来源` 之外的语义等价不算命中，这是保守口径。
4. **不测下游正确率**：那是第三项指标，需要真实任务集。
5. **模型会写含糊**：压缩的第一反应是删「看起来重复」的内容，而消歧信息恰恰看起来最重复。lint 只能挡一部分，挡不住「正确地写错」。
